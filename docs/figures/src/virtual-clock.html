Why the game runs on a virtual clock

A vision model needs seconds per decision, and a CPU-only machine renders the 3D samples at 2–5 frames per second. In real time both end up on the video. Under the virtual clock the game advances only when the agent steps a frame, so thinking costs wall time and no game time.

The game keeps running while the model thinks. The viewer sees a player who freezes for seconds between moves, and a fast game is lost before the first input. Three decisions take 11.6 s of video.

Virtual clock: what this system records

The same three decisions. Each planner call collapses to a zero-width mark on the video; the only pauses left are the ones a person would make. The same decisions take 4.4 s of video, and every frame is exactly 1/30 s of game time after the previous one.
