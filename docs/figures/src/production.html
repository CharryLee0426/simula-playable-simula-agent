Running it on hundreds of new playables a week

The prototype already has the production shape: one playable is one durable session task, every phase is idempotent against its output, every paid call is in a ledger. Production adds a queue, isolation, caching, budgets and a person for the cases the evaluator is unsure about.

Intake

  • upload to object storage
  • content hash, dedupe, priority
  • static lint: size, network calls, ad SDKs
→

Queue

  • SQS, Pub/Sub or Temporal
  • 2–3 takes per playable: other seeds and personas
→

Worker pool: one container per session

Chromium + Xvfb or GPU + ffmpeg + agent. No network egress from the browser. CPU, memory and time limits; a hung page is killed by the phase timeout and retried once.
Durable session task: play → index → cut → render → eval → friction → report, checkpoint per phase. A crashed worker resumes at the last committed phase and never pays twice.
→

Routing by the evaluator

Publishgate ok and score above the pass line
Human reviewborderline score, or judge and heuristics more than about 20 points apart
Retry, then reviewfailed: another seed or persona first

Storage

  • object store: raw.mp4, highlight.mp4, candidates, trace.html, logs
  • Postgres: sessions, phase checkpoints, ledger rows, scores, friction items, review decisions

Cache keys

  • playable_sha → game model, moments, friction
  • + seed + persona → raw capture; a re-cut costs about $0.05

Budgets and models

  • per-session cap before every call; weekly cap per customer
  • over budget, phases degrade instead of failing
  • cheap planner by default, stronger one when the decider reports low clarity or a stuck player

Operations

  • nightly regression on samples, generated and hold-out games with fixed seeds
  • a drop of more than 5 points on any game blocks a prompt or model change
  • config, model ids and code version stored per session
Calibration loop. Every review decision (approve, re-cut, reject, with a reason) is stored next to the scores. Weekly, the score weights are refitted on those decisions, and shipped highlights report CTR and IPM back as the real target. Friction reports go to the playable’s creators with the same trace links.
