System architecture

Two processes. The browser worker owns the game, its clock and the recording. The agent owns every decision and runs as one durable task per playable, with a checkpoint after each phase. Nothing in either process knows a particular game.

game.htmlany single-file HTML5 playable, never seen before: canvas 2D, DOM or WebGL 3D
→
./run --playable game.html --out highlight.mp4one command, one OpenRouter key

Browser worker Python · Playwright · Chromium (headed on Xvfb, or headless)

Virtual clock (injected shim)
  • rAF, timers, performance.now, Date, event timestamps, CSS / Web Animations and AudioContext.currentTime advance only when the agent steps a frame
  • seeded Math.random
Sandbox
  • ad SDK stubs: mraid, dapi, ExitApi, FbPlayableAd
  • every non-file request aborted, WebSocket never connects
  • CTA calls logged as events
Capture
  • every stepped frame → JPEG → ffmpeg, 30 fps H.264
  • audio event log → offline mix in game time → raw.mp4
Generic perception
  • input listeners the game registered
  • interactive DOM elements (set-of-marks)
  • player tracker and impact signatures for reflex play
JSON lines over stdin / stdout: step · touch · observe · peek  ↓    screenshots, DOM, listeners, motion stats  ↑

Agent TypeScript · one Pi Durable SessionTask per playable · SQLite checkpoints · every paid call in a ledger with a budget cap
